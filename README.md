# ИИ-ассистент в Telegram (с личного аккаунта, без бота)

Ассистент работает под **вашим** аккаунтом через MTProto: читает входящие личные сообщения,
генерирует ответ через LLM и отправляет его как обычное сообщение. Со стороны это выглядит
как переписка с вами. Бот не создаётся и не нужен.

Дополнительно: можно просто писать в «Избранное» (Saved Messages) — ассистент ответит там
(`SELF_CHAT_MODE=true`).

## Быстрый старт

1. Создайте приложение: [my.telegram.org](https://my.telegram.org) → **API development tools** →
   скопируйте `api_id` и `api_hash`.
2. Запустите `setup.bat` — он поставит зависимости, спросит ключи и проведёт вход в Telegram
   (номер → код из Telegram → пароль 2FA, если включён).
3. Запустите `start.bat`.
4. Напишите себе в «Избранное»: `/status` — придёт отчёт.

Автозапуск при входе в Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\autostart.ps1          # включить
powershell -ExecutionPolicy Bypass -File .\autostart.ps1 -Remove  # выключить
```

## Как это работает

```
входящее ЛС → фильтры (не бот, не канал, blacklist/whitelist, пауза)
   → склейка серии сообщений (2.5 с тишины)
   → «печатает…» + запрос к LLM с историей диалога
   → пауза «на подумать» → отправка (длинное режется на части)
   → запись в SQLite
```

Если вы сами ответили человеку, ассистент замолкает в этом диалоге на
`OWNER_TAKEOVER_MINUTES` минут (по умолчанию 30) — чтобы не перебивать вас.

## Команды (пишите в «Избранное»)

| Команда | Действие |
|---|---|
| `/status` | состояние, статистика, лимиты |
| `/pause` | ассистент молчит для всех |
| `/resume` | снова отвечает |
| `/reset` | очистить память всех диалогов |
| `/prompt <текст>` | заменить системный промпт на лету |
| `/prompt reset` | вернуть промпт из `.env` |
| `/block <id\|@username>` | не отвечать человеку |
| `/unblock <id\|@username>` | снять блок |
| `/takeover <минуты>` | сколько молчать после вашего ручного ответа |
| `/help` | список команд |

## Запись новых сообщений в таблицу

Каждое новое сообщение дописывается строкой вниз таблицы `TelegramChannel`
([http://127.0.0.1:8787](http://127.0.0.1:8787), проект `DAVINCHI\sheetdesk`).

| Колонка | Что попадает |
|---|---|
| `Date` | время события `ДД.ММ.ГГГГ ЧЧ:ММ:СС` |
| `From` | имя отправителя (`Jedi`, `ИИ-ассистент`, имя собеседника) |
| `Id` | Telegram id чата |
| `Username` | `@username`, если есть |
| `Message` | текст входящего сообщения (или ваше сообщение из «Избранного») |
| `Reply` | ответ ассистента отдельной строкой ниже |

Особенности:

- Колонки берутся из `SHEET_COLUMNS`; сопоставление по названию (регистр и язык не важны:
  `Date`/`Дата`, `Message`/`Сообщение`, `From`/`От`, `Reply`/`Ответ`).
- Пустые строки между записями не появляются: ниже заголовка пишется только заполненное.
- Если таблица недоступна, ассистент продолжает отвечать в Telegram, а ошибка пишется в лог.
- Если однажды пропала строка — проверьте, что SheetDesk запущен (`/api/health`).
- Указывайте `SHEET_WORKBOOK` **id-шником** (uuid): имена не уникальны, и при двух таблицах
  с одинаковым названием ассистент откажется писать (в логе будет подсказка).

## Реально-временная запись в Supabase (supabase.com)

Помимо локальной SQLite и таблицы SheetDesk, каждое сообщение можно дублировать в
**базу данных проекта Supabase** — в реальном времени, неблокирующе (сбой Supabase не
останавливает переписку).

Что попадает в таблицу: входящие сообщения из личек, групп и каналов, ответы ассистента,
ваши ручные ответы и сообщения в «Избранном». Медиа (картинки, файлы) загружаются в
**Storage** Supabase, а в строке сохраняется их публичный URL.

Настройка (`.env`):

| Переменная | Смысл | По умолчанию |
|---|---|---|
| `SUPABASE_URL` | Project URL проекта (`https://<ref>.supabase.co`) | — |
| `SUPABASE_KEY` | anon (публичный) ключ проекта | — |
| `SUPABASE_TABLE` | таблица для сообщений | `messages` |
| `SUPABASE_BUCKET` | ковш Storage для медиа | `messages` |
| `SUPABASE_WRITE_REPLIES` | писать ли ответы ИИ отдельной строкой | `true` |
| `SUPABASE_LOG_OWNER` | писать ли ваши ручные ответы | `true` |

Один раз подготовьте проект Supabase:

1. В **SQL Editor** вашего проекта выполните `bootstrap.sql` — создаст таблицу
   `messages` (с RLS-политиками на insert/select) и ковш `messages`.
2. Возьмите `SUPABASE_URL` и anon-ключ: **Project Settings → API → Project URL / anon key**.
3. Впишите их в `.env`. Пустой `SUPABASE_URL` = запись в Supabase выключена.

Заголовки колонок таблицы `messages`: `created_at, channel, sender, username, chat_id,
message, reply, media_url, media_type, chat_title, chat_username, sender_id, direction`.
Менять можно, но тогда поправьте `build_row` в `supabase_sink.py`.

Если таблица создана до появления полей чата, выполните `bootstrap.sql` ещё раз —
он идемпотентен и добавит `chat_title`, `chat_username`, `sender_id`, `direction`.
До миграции ассистент продолжает работать: название и username чата в этом случае
дописываются в колонку `channel`, а `direction` — суффиксом «исходящее».

## Группы и каналы

Раньше сохранялись только личные сообщения: обработчик отбрасывал всё, где
`event.is_private == false`. Теперь сообщения из групп, супергрупп, каналов и
пабликов тоже пишутся в SQLite (`chat_log`), SheetDesk и Supabase.

Что сохраняется:

- тип чата (`Группа` / `Канал`), `chat_id`, название и `@username` чата;
- id, имя и `@username` отправителя (для поста канала — сам канал);
- текст или подпись к медиа, `media_url` и `media_type`;
- направление: `in` — входящее, `out` — ваше сообщение.

Важно:

- Ассистент **не отвечает** в группах и каналах — только сохраняет. Личка работает как раньше.
- Журнал групп/каналов лежит отдельно от истории личек, поэтому не влияет на память LLM.
- Медиа скачивается только при `LOG_CHAT_MEDIA=true`; в Supabase попадает публичный URL.
- Для очень активных пабликов логирование можно выключить: `LOG_CHANNELS=false`.
- `/status` в «Избранном» показывает число чатов и сохранённых сообщений из них.

## Деплой на Render (free)

Сервис: **https://telegram-assistant-v8pj.onrender.com** (Франкфурт, план free).
Проверка живости: `/healthz` → `ok`.

- Сборка и запуск — `render.yaml` (build: `pip install -r requirements.txt`, start: `python main.py`).
- Сессия Telegram передаётся строкой `TG_SESSION_STRING`; файловая сессия используется только локально.
- `api.render.com` из сети владельца заблокирован, поэтому управление (деплой, логи)
  идёт через GitHub Actions: workflows `render-deploy`, `render-fix`, `render-logs`.
  Ключ Render API и полный payload настроек лежат в зашифрованных секретах репозитория
  (`RENDER_API_KEY`, `DEPLOY_PAYLOAD`).
- **Не засыпать:** free-план засыпает через 15 минут без HTTP-запросов. Workflow `keepalive`
  пингует `/healthz` каждые 5 минут по расписанию GitHub Actions.
- **Важно:** сессия одна — нельзя запускать локальный `start.bat`, пока сервис жив на Render.
- Обновление env-переменных через API: `PUT /v1/services/{id}/env-vars`, затем новый деплой
  (создание сервиса с envVars в payload их не применяет — проверено).

## Важно про риски

- Автоматизация личного аккаунта — серая зона правил Telegram. Лимиты, задержки и
  «молчание после вашего ручного ответа» снижают риск, но не убирают его полностью.
- Отвечаем только тем, кто написал первым. Никаких рассылок и вступления в группы.
- Файл `data/assistant.session` даёт полный доступ к аккаунту — не выкладывайте его.
- Если Telegram ограничит отправку (FloodWait), ассистент переждёт и продолжит.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `Сессия не авторизована` | `python login.py`, затем `start.bat` |
| `api_id/api_hash отклонены` | значения с my.telegram.org, без пробелов |
| Ответы не приходят | `LOG_LEVEL=DEBUG` в `.env`, смотрите `data/assistant.log` |
| `Ошибка авторизации/модели` | `LLM_API_KEY`, `LLM_BASE_URL`, название модели |
| Медленно отвечает | уменьшите `HISTORY_LIMIT`, смените модель |

Проверка без запуска: `python tests\live_check.py` и `python tests\selftest.py`.
