# ИИ-ассистент в Telegram — описание проекта и архитектуры

## 1. Что это

Ассистент работает **под вашим личным аккаунтом Telegram** (userbot на MTProto через Telethon),
а не через Bot API: читает входящие личные сообщения, генерирует ответ через LLM и отправляет
его как обычное сообщение. Для собеседника это выглядит как переписка с вами. Бот не создаётся.

Стек: Python 3, `telethon`, `openai` (OpenAI-совместимый API), `python-dotenv`, `httpx`, SQLite.
По умолчанию LLM — Inception Labs Mercury; поддерживается DeepSeek, OpenAI, локальный Ollama.

## 2. Ключевые функции

### Ответы от вашего имени
- **Два режима в одном коде:** `A` — автоответчик для контактов, которые пишут в личку;
  `B` — личный чат с ИИ в «Избранном» (`SELF_CHAT_MODE`).
- **Контекстная память** по каждому диалогу: последние `HISTORY_LIMIT` сообщений из SQLite.
- **Системный промпт** подстраивается под владельца (`OWNER_NAME`), стиль — «как живой человек»:
  коротко, без списков и markdown.
- **Ротация промпта на лету** командой `/prompt` без перезапуска.

### Человечность и защита от «робота»
- **Дебаунс** (`DEBOUNCE_SECONDS`, 2.5 с): серия быстрых сообщений склеивается в один ответ.
- **Индикатор «печатает…»** на всё время генерации.
- **Задержка по длине** ответа (`MIN_DELAY`–`MAX_DELAY`) со случайным разбросом.
- **Нарезка длинных ответов** по абзацам/предложениям без разрыва слов (`TELEGRAM_LIMIT` 3800).
- **Чистка markdown** — никаких `**` и списков в отправленном тексте.
- **Раскрытие ИИ** одним разом на диалог (`DISCLOSE_AI`, флаг `disclosed` в БД).

### «Не мешать владельцу»
- **Owner takeover:** если вы сами ответили человеку, ассистент молчит в этом диалоге
  `OWNER_TAKEOVER_MINUTES` минут (меняется `/takeover`).
- **Отсечение своих отправок** (дедуп по паре «чат + текст» с окном 10 с) — нет двойных сообщений.

### Фильтрация получателей
- Только личные чаты; игнорируются боты, каналы, группы.
- **Blacklist / whitelist** (`REPLY_SCOPE=all|whitelist`), учитываются и `id`, и `@username`.
- **Пауза** глобальная (`/pause`) и по собеседнику (поле `paused` в БД).
- Отвечаем только тем, кто написал первым — без рассылок.

### Лимиты и устойчивость
- `MAX_REPLIES_PER_HOUR` (40) и `MIN_GAP_SECONDS` (20) на диалог.
- Переживание **FloodWait** (спит нужное число секунд и продолжает).
- Ретраи LLM: 3 попытки с нарастающей паузой; отдельная обработка 401/403/404/400.
- Переподключение Telethon, ротация логов (2 МБ × 3), автозапуск через Task Scheduler.

### Управление командами из «Избранного»
`/status` (статистика, лимиты, модель), `/pause`, `/resume`, `/reset`, `/prompt [текст|reset]`,
`/block <id|@username>`, `/unblock`, `/takeover <минуты>`, `/help`.

### Вложения
- **Фото и картинки-документы:** скачивание, сжатие до 1600 px по длинной стороне, конвертация
  в JPEG, отправка в модель как `data:` URL.
- **Фолбэк на vision-модель:** если основная модель картинку не принимает, отдельная модель
  описывает изображение, и основная отвечает по описанию.
- **Текстовые документы** (до 18 МБ, до 12 000 символов) подмешиваются в контекст.
- **Прочие типы** (голосовые, видео, стикеры, контакты, гео) не распознаются, но описываются
  словами, чтобы модель понимала, что ей прислали.

### Экспорт в таблицу (SheetDesk)
- Каждое сообщение дописывается строкой вниз листа Univer-таблицы (`http://127.0.0.1:8787`).
- Колонки настраиваются по названию (`SHEET_COLUMNS`), сопоставление терпимо к языку
  (`Date`/`Дата`, `Message`/`Сообщение`) и регистру.
- **Картинки вставляются в лист** как drawing-объекты, привязанные к строке.
- Пишутся входящие, ответы ИИ и ваши ручные ответы (`SHEET_WRITE_REPLIES`, `SHEET_LOG_OWNER`).
- Запись неблокирующая: если таблица недоступна, ассистент продолжает отвечать, ошибка — в лог.
  Защита от дублей таблиц по имени требует указывать `SHEET_WORKBOOK` как uuid.

### Настройка и диагностика
- `setup.bat` / `setup.py` — мастер: зависимости, api_id/hash, номер, ключ LLM → `.env`.
- `login.py` — вход по номеру/коду/2FA и проверка авторизации сессии.
- Офлайн-тесты без сети против фейковых Telegram/LLM/SheetDesk.

## 3. Архитектура (кратко)

```
Telegram (MTProto)
      │  NewMessage(incoming=True)  /  NewMessage(outgoing=True)
      ▼
┌───────────────────────── handlers.Assistant ─────────────────────────┐
│ 1. Фильтры: личка → не бот → self/Избранное → blacklist/whitelist     │
│    → пауза (глобальная / по peer / owner-takeover)                    │
│ 2. Вложения: attachments.extract() — фото/док → текст + data-URL      │
│ 3. Дебаунс: буфер по peer_id, таймер перезапускается на каждом сообщ. │
│ 4. Лимиты: реплики за час, минимальный интервал, блокировка на диалог  │
└───────────────┬──────────────────────────────────────────────────────┘
                │  _generate()
                ▼
        llm.LLM.reply()  ── system prompt + история из SQLite ──►  LLM API
                │                                                  (OpenAI-совм.)
                │  clean_text → split_text → «печатает…» + задержка
                ▼
        handlers._send()  ──►  Telegram send_message (FloodWait-aware)
                │
        ┌───────┴────────┐
        ▼                ▼
  store.Store      sheets.SheetsSink
  (SQLite)         (HTTP → SheetDesk)
```

### Слои и модули

| Слой | Модуль | Ответственность |
|---|---|---|
| Вход | `main.py` | Сборка зависимостей, логирование, connect/run, graceful shutdown |
| Конфиг | `config.py` | Чтение `.env`, dataclass `Config`, валидация, дефолтный промпт |
| Транспорт | `main.py` + Telethon | Сессия, событийная модель |
| Домен | `handlers.py` | Фильтры, дебаунс, лимиты, «человечность», команды, отправка |
| LLM | `llm.py` | Промпт + история, ретраи, fallback на vision, чистка и нарезка текста |
| Вложения | `attachments.py` | Скачивание, сжатие, классификация, описание для модели |
| Хранилище | `store.py` | SQLite: `messages`, `peers`, `kv`; потокобезопасен (`RLock`) |
| Экспорт | `sheets.py` | Дописывание строк и картинок в Unify/Univer-снимок через REST |
| Вход в аккаунт | `login.py`, `setup.py` | Сессия, мастер `.env` |

### Данные

- **SQLite `data/assistant.db`:** `messages` (история по `peer_id`, роль `user|assistant|owner`),
  `peers` (профиль, `disclosed`, `paused`), `kv` (глобальная пауза, override-промпт,
  blacklist, takeover-минуты, `owner_active_<peer>`).
- **Файлы:** `data/assistant.session` (доступ к аккаунту — не выкладывать), `data/assistant.log`.
- **Ключи** только в `.env` и только локально; в git не попадают.

### Ключевые архитектурные решения

1. **userbot вместо бота** — принципиальный выбор: только MTProto даёт сообщения от вашего имени
   и доступ к личным перепискам.
2. **Асинхронное ядро** — дебаунс и параллельность по диалогам на `asyncio` (таймеры, задачи),
   блокирующие операции (SQLite, HTTP) выносятся в `asyncio.to_thread`.
3. **Изоляция по диалогу** — `asyncio.Lock` на `peer_id` защищает от гонки при одновременной
   генерации и отправке.
4. **Экспорт как side-channel** — `SheetsSink` полностью необязателен и не блокирует ответ:
   сбой таблицы логируется, переписка продолжается.
5. **Конфиг через env** — никакой правки кода для поведения; команды в «Избранном» покрывают то,
   что нужно менять на ходу.

## 4. Риски

Автоматизация личного аккаунта — серая зона правил Telegram. Лимиты, задержки и молчание после
вашего ручного ответа снижают риск ограничений, но не убирают его. Рекомендуется отдельный номер.
